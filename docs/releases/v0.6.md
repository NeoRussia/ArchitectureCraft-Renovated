A fix release for the shader work in 0.5. A glowing glass shape emits light
again, and Distant Horizons stops drawing shapes as missing textures.

Fixes
-----
- **A glowing translucent shape emits light again.** A shape's own light was
  hard-coded to zero in the per-block context the shader pack reads as block
  emission. A glowing shape whose material is translucent has to report the
  material's glass id, so that it keeps its tint, and an id is the only place
  that light would otherwise have gone. The result was a shape the pack saw as
  glass that emits nothing, and it dropped out of the light grid entirely. The
  shape's own light now travels with that context. Eclipse reads it for glass
  ids as well as unmapped ones, so a lamp cut from glass lights the room again;
  the cell stops tinting while it is an emitter, because one cell carries one
  id. Opaque lamp shapes are unchanged, their id already says they are lit.
- **Distant Horizons no longer draws shapes as missing textures.** Its LOD
  renderer bakes one texture per block state, and a shape's state carries no
  sprite: the material lives in the tile entity. Every distant shape therefore
  came out as the pink missing texture while the blocks around it were fine. A
  shape's model now answers with a plain stone sprite, so a distant build reads
  as solid stone. The same change removes a null that any renderer asking a
  shape for its quads could trip over.
- **Any glass-like material can be cut.** The sawbench decided what it accepted
  by block name and by whether the block reports itself as a full cube. Glass is
  neither: it is deliberately not a full cube, and outside vanilla its name says
  nothing. Xtones' Glaxx and other modded glass were refused for that reason.
  The material decides now, so anything built on glass is accepted, with panes
  left out because there is no cube to cut from them. Vanilla glass and stained
  glass behave as before.
- **Shapes whose mesh overhangs the block can be picked again.** A converted
  model can have bounds a 256th above the block top, or a capital or a roof
  overhang can sit outside the cell entirely. The selection box was built from
  those bounds, so the ray was already inside it by the time the block's own
  cell was tested: the near face was never reported and a click on the top
  landed on whatever was behind it, so no block could be placed on the shape.
  It is the fence failure again, from a different box. The selection box is now
  clipped to the block.

Requirements and install
------------------------
- Minecraft 1.12.2, Forge 14.23.5.2860, Java 8. Cleanroom 0.7.x works too.
- No required dependencies. The One Probe support appears once it is installed.
  The shader block ids need Demonica, a single jar which carries the Iris-based
  pipeline and its own Celeritas build, and do nothing without it or with
  shaders switched off.
- Drop the jar into `mods/` and start the game. Existing worlds keep their
  shapes and their orientation.
- Both switches live in the mod's config screen and in
  `config/architecturecraft.cfg`.

Known limitations
-----------------
- **At Distant Horizons distance every shape is stone.** Its LODs are keyed on
  the block state and a shape's material is in the tile entity, so the far view
  cannot match what was built. If you would rather have shapes absent beyond
  render distance than uniform, add `architecturecraft:shape` to
  `ignoredRenderBlockCsv` in `DistantHorizons.toml`, then let Distant Horizons
  regenerate its LODs.
- **The six tool item models are still generated at runtime.** Circular Saw
  Blade, Chisel, Hammer, Large Pulley, Paintbrush and Cladding have textures but
  no model files in the jar; a bundled resource-pack generator builds them per
  item on demand, and the Sawbench is the exception with a real model. Where
  that generator does not run, or where a resource pack ships those paths and
  shadows it, the tools show the missing model while the Sawbench renders
  normally. Shipping the files is the fix; this build does not do it yet.
